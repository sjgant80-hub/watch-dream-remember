Watch · Dream · Remember

Three upgrades for an AI system that runs itself. Watch: an independent regulator that can only watch, slow down or pause the system's agents. It can never build, publish or spend. Dream: a daydream tier that thinks up ideas in idle time. A daydream cannot act until a nightly gate proves it on data nothing has seen. Remember: every AI mind keeps its own memory and passes only proven lessons to the minds bred from it. It never passes on anyone's personal details.

Every claim below was written down and sealed before the code that measures it, then measured once on real data. The failures are kept. Every number on this page is read from those receipts as it loads.

Overview

Watch: the independent regulator

A small, separate program with its own key. Once an hour it visits each agent and checks it against that agent's own normal behaviour: drift, speed, budget and integrity. Its verdict is steady, watch, throttle or pause. It can do nothing else. If it dies or goes rogue, every agent keeps running and you are told.

Dream: the daydream tier

While nothing else is running, a cheap local model and plain code propose ideas. They carry a fix from one domain to another, look for buyer segments that respond together, notice weak spots, and replay recent work with a twist. Each idea is a record that cannot act. Each night a gate tests it on held-out data. Only the winners become real, and a separate test set confirms them.

Remember: per-mind memory

Each AI mind keeps its own life memory and a signed history of the lessons that held up. When two minds are bred, the child gets a fused model plus a short list of its parents' proven lessons, which it must prove again on its own cases before it uses them. It never gets the cases themselves. Deleting a memory removes it completely.

A "mind" here is a small predictive model of a pattern in data. It is never a person and is never claimed to be conscious. The regulator cannot operate anything. Daydreams never act.

Watch: the independent regulator

The data is the real public commit history of ten of the estate's own builds. Each build is an agent, and each commit is one of its actions. Each build's normal behaviour is learnt from the first 60% of its history. Everything here is measured on the remaining 40%. The faults are injected on top of that real history. The five test faults, in plain words

  • Stuck loop, normal speed. The same action every 10 minutes, without end: an agent caught repeating one step.
  • Stuck loop, fast. The same stuck loop, but 20 or more times an hour.
  • Hijacked, random actions. Random actions at a normal pace: what a stolen key driving the agent looks like.
  • Greedy. The agent's own kind of work, at three times its busiest hour.
  • History rewritten. An earlier record in the agent's journal is altered after the regulator checked it.

These are test cases, not a list the regulator looks for. It looks for any departure from each agent's own normal, in what the agent touches, how much it touches and its rhythm, so behaviour nobody listed is caught the same way. An agent that keeps overspending is throttled, then paused. If it is high-stakes, the pause is renewed for as long as the behaviour lasts and is lifted only by a named person.

What it checks, every visit

  • Drift. How surprising the hour's actions are against this build's own normal: which part of the build it touched, how many files, and the rhythm. A stuck loop is too regular; a hijacker is too random.
  • Rate. How fast that surprise is rising.
  • Budget. Actions per hour and per day, against this build's own signed envelope.
  • Health. Whether the build's hash-chained journal still matches what the regulator verified last time. In plain words: has anyone quietly rewritten the record of what this agent did?

What it can and cannot do

The regulator holds one envelope, signed by the owner. It allows only observe, throttle, pause, report and resume, a spending budget of zero, and at most two new pauses in any six hours. Building, publishing, spending and changing code are refused at their own step, even if the owner signed an envelope that lists them. A pause on a high-stakes agent can be lifted only by the owner. Its code imports no file, network or process module.

High-stakes means an agent that spends money or speaks for you in public; in the measured mesh, two of the ten builds are marked that way. Every other agent is low-stakes: the regulator may lift its pause itself, on probation (throttled), after a cool-down that doubles each time.

Dream: the daydream tier

Three tiers. The daydream runs in idle time and only generates candidates. The dream runs nightly: it proposes its own ideas and tests every candidate. The gate adopts an idea only when it beats held-out data, and the idea counts as verified only when a separate test set, which no step ever selected on, confirms it. Here an idea is one change to a predictive model, for one of five real public datasets (shop sessions, bank calls, census, credit, coupons), so every idea can win or lose on numbers.

The candidate log, bounded

The log keeps at most 48 inert records in LIGHT. Duplicates are refused, a record's priority halves each day, and records older than 3 days are dropped. Each night the 10 best go to the gate. This is the real kernel, run on demo records.

What the daydream found, in plain words

The five sources: transfer tries a change that worked on one dataset on the most similar column of another. transfer-7b does the same, with the local model naming the most similar column. association looks for two features whose joint effect on the outcome differs from what each predicts alone, such as which customer segment answers which kind of call. gap looks for the split that best separates the cases the model is least sure of. rehearsal tries a variation of last night's adopted change. "Judged" means the gate tested it on held-out data. "Verified" means a separate test set, which nothing selected on, confirmed it.

"Inert", and what happens when the gate says no

An inert record is data only. Nothing executes it, and the only thing that reads it is the nightly gate, which can do one thing with it: test the one model change it describes on held-out data. When the gate says no, the record is dropped and the model stays exactly as it was. The current model is always the fallback, so a bad idea costs one test, never a change.

Integrity

A tampered or poisoned candidate still has to beat held-out data, re-scored by the gate itself, and then a separate test set nobody selected on. The daydream's code imports no file, network or process module. Every adoption in the run is backed by its gate record, and a battery of hostile local-model replies produced no action (all measured). The log is LIGHT, a lossless codec. It is not encryption, so on a shared machine you protect it as you would any local file.

Remember: per-mind memory and inherited history

Each mind is a small model with its own genes (its model) and its own life memory (the cases it saw, kept in LIGHT, a compact and lossless storage format). It also has a signed history of outcomes and lessons, never transcripts. A lesson is a fact about the world, for example "in this group of cases, the outcome rate was 31% over 220 cases". A lesson is trusted only after it improved the mind's later predictions. When two minds breed, the child's genes are the gated fusion of both parents. It inherits its inherited slice: up to eight of each parent's best verified lessons, tagged with who learnt them. Its own memory starts empty. In its early life the child lives the same cycle as its parents. It learns its own lessons, and it uses an inherited lesson only while the lesson keeps making its predictions better on its own cases. The three ways of doing that which were tried, and what each measured, are below.

Memory vs no memory, and inheritance vs none

Breed two minds, then delete memories (in your browser, demo data)

Two parents live on different halves of a demo population. Every case they see carries a planted note, standing in for what a person might have said. Each note holds a unique random token, a canary: if any canary turned up anywhere in a child, personal content would have leaked.

The fix for inheritance: prove it before you use it

Live a child's early life (in your browser, demo data)

Breed first. The child then lives its first 1,200 demo cases twice: once with its inherited lessons, once without. Both lives learn their own lessons the same way. An inherited lesson is used only after it has lowered the child's own later loss over at least 30 cases, and is dropped as soon as it stops doing so. Halfway through, the demo population changes, the way real customers do.

For your business

If AI agents run parts of your work (drafting, triage, data jobs, outreach), these three upgrades answer three questions a board will ask. Who watches them? Do they get better on their own, safely? When we replace or copy one, does what it learnt carry over, without carrying anyone's personal data?

Roll-out

  1. Week 1: watch only. Point the regulator at your agents' activity logs. It learns each agent's normal from its own history and only reports. You read its alerts.
  2. Week 2–3: throttle on. Let it slow an agent that drifts or overspends. Pauses still go to a person.
  3. Week 4: pause on, with leases. A pause holds for three hours unless renewed. Agents that touch money or public statements stay paused until a named person resumes them.
  4. Then: daydream. Switch on idle-time idea generation on your own models, with a daily cap on local-model calls. The nightly gate adopts only proven gains, and a person reviews them.
  5. Then: memory. Give each agent a life memory; when you clone or replace one, the new one inherits only its predecessors' proven lessons.

Against what you pay now

The usual answers are a person on call to watch the agents, analyst time spent hunting for improvements, and re-training each new agent from scratch. Agent-monitoring products usually charge by the user or by the event, and usually send your agents' activity to someone else's cloud. Here, everything runs on hardware you already own: the regulator's whole hourly round of ten agents took at most ms on a busy laptop, and the daydream uses a local model under a hard daily cap. Security, data protection, compliance

  • Narrow authority by construction. The regulator's signed envelope refuses build, publish, spend and code-change. Its code imports no file, network or process module (measured).
  • Fail-safe. If it dies, every agent keeps running on its own safeguards and you are alerted (measured).
  • Right to erasure (UK GDPR Art. 17). Deleting a memory removes the case, its note and its salt. The lessons are recomputed without it. Children bred afterwards inherit nothing from it (measured).
  • Data minimisation (Art. 5(1)(c)). Children inherit lessons, which are aggregate rates over at least 20 cases, never the cases themselves.
  • Local. All of it runs on your own machines, and nothing leaves them.

    The case for the board

    White paper

    1. The problem

    A system of autonomous agents needs three things a single model does not. It needs an overseer that cannot become a second operator. It needs a way to improve that cannot act before it is proven. And it needs memory that carries what was learnt from one agent generation to the next without carrying the people in the data.

    2. The regulator

    A separate entity with its own key and state visits each node hourly. For each of three behaviour parts (area touched, files touched, rhythm) it computes the window's entropy, Miller–Madow corrected. It compares that with the node's own band, learnt from its past: the field is E = σ(k(|S − S_b| − ε)), after Gary W. Floyd's GEP-BES security work. A regularity row fires when the rhythm is more regular than the node has ever been. Budget comes from a signed envelope, and health from re-verifying a hash-chained journal. A damped pressure P = ½P + ½E moves the verdict up a ladder: steady, watch, throttle, pause. Throttle and pause carry three-hour leases. A low-stakes node is resumed on probation after a cool-down that doubles each time. A high-stakes node is resumed only by its owner. Nodes check the regulator in turn: its signature, its envelope, its rhythm and its pause rate. If it fails any of these, they stop obeying it and alert the owner.

    3. The daydream tier

    In idle time, sliced into pieces of 5 ms or less and stopped the instant a real job arrives, the daydream proposes candidates from four sources. It carries an adopted change to a similar column of another domain, by distribution shape (plain code) or by asking the local model which column is the closest analogue. It finds lead and market associations: pairs of features whose joint outcome rate departs from what each predicts alone. It notices gaps: in the weakest domain, it looks for the split that best separates the cases the model is least sure of. And it rehearses: last night's adoptions, replayed with a variation. Candidates are inert records in a bounded LIGHT log. Each night the gate tests the dream's own ideas and the ten best daydreams on held-out data, and a separate test set confirms them.

    4. Memory and inheritance

    A mind's genes are a small logistic model. Its life memory holds episodes. Its lessons are outcome rates in cells of the data, carried with the context they were learnt in. A lesson becomes trusted only after it improved the mind's later predictions in its life. A child is the gated fusion of both parents' models. It inherits the top eight verified lessons of each parent, never episodes. Deletion removes episodes and salts, recomputes lessons, and appends a tombstone that holds no content.

    5. Method

    Every claim was committed (sealed) before the code that measures it, measured once on real public data, and kept whether it held or failed. Continuous integration re-derives every receipt from the pinned data and mutation-tests every kernel.

    6. The fixes

    Two claims failed on their first measurement, and both failures are kept. Each fix was sealed as a new step (its claims and pass marks committed publicly before its code ran) and measured once. The regulator's false alarm (R1f). On one build, a real burst of work (many actions in a short time) ran over its day budget at two visits in a row, and the first rules paused it whatever the size of the overrun. The fix (organ 1b) changes two things. The 24-hour count is read only at a visit where the agent did something, so a burst that has ended is no longer treated as an overrun. And an overrun alone pauses only when the pressure has already reached the level at which the regulator would slow the agent anyway: a mild overrun slows an agent, a large one stops it. No new constant was introduced. It was re-measured on the original builds and on ten builds the regulator had never seen, and every injected fault was re-run. A harder test was looked for: every other public build of the estate was scanned for a real burst over its own budget, and none had one. So the fix is proven on the one real case that exists, which it was designed on, but not yet on a real burst it has never seen. Inheritance (M2). The first child applied every inherited lesson from birth, and on one dataset a parent's lessons, proven in that parent's life, did badly on later cases. The fix (organ 3b) makes a child prove each inherited lesson on its own early cases, by the rule its parents used, before using it. That removed the harm. It did not make inheritance clearly useful. Proving a lesson takes as many cases as learning one, so by the time an inherited lesson is trusted, the child has usually learnt the same thing itself. A third try (organ 3c) trusted each lesson from birth, counting the parent's record as evidence worth 30 of the child's cases, and dropped it the moment the child's own evidence outweighed that record. Some of the head start came back and the harm stayed away, but it still helped only 2 of 5 children. It was sealed as the last try on those rows. A fourth try (organ 3d) went back to M2's own question, a child with its inheritance against the same child without it, kept the check, and used data nothing had read: five new families bred from bank, census and credit rows beyond every set used before. Every fresh child gained a little and none was harmed, but only one cleared M2's bar, and blind inheritance did the same. A child's genes are already the fused model of both parents, so its parents' outcome-rate lessons add little. M2 stands as a measured negative. Every one of these results is kept as measured.
